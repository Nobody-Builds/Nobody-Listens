# Nobody Listens notes for Claude

## Build and test (Windows)

- `minSdk` is 33 (Android 13). It was 35 after the rebrand, but lint's `NewApi` check at 33 found no unguarded Android 14/15 calls (2026-10-20). Rerun that check before using any new platform API.

- JDK: Android Studio's bundled one. Set `JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"` and `ANDROID_HOME="%LOCALAPPDATA%\Android\Sdk"` (there is no `local.properties`).
- `./gradlew :app:assembleDebug` builds ABI-split APKs (arm64-v8a, armeabi-v7a). The x86_64 `Pixel_8a` emulator runs the arm64 APK through translation.
- Unit tests are JUnit 5: `./gradlew :app:testDebugUnitTest --tests "com.nobodybuilds.listens.data.ytmusic.*"`.
- `YouTubeMusicStreamTest` has a live test that hits YouTube. It only runs with `YTMUSIC_LIVE=1` in the environment.

## Identity (Nobody Listens, a fork of LMusic)

- The app is **Nobody Listens**, a fork of LMusic by Abhiram NJ (itself built on PixelPlayer). About and the README credit both; keep that credit.
- `applicationId` is `com.nobodybuilds.listens` on phone and watch (they must match, and share a signing key, for the Wear Data Layer). Kotlin packages and `namespace` are `com.nobodybuilds.listens` too (shared: `.shared`, baseline profile: `.baselineprofile`). Classes use `NobodyListens*` (`NobodyListensApplication`, `NobodyListensDatabase`, `NobodyListensHaptics`…), Gradle flags `nobodylistens.*`, and the CI secrets `NOBODY_LISTENS_KEYSTORE_B64` / `_PASSWORD` / `NOBODY_LISTENS_KEY_ALIAS`. Stored-data names keep their LMusic form **on purpose** so LMusic backups and taste codes still import: the `"lmusic_*"` DataStore/prefs names (backup `FeatureStoreSpec` keys), the Room DB file name, the backup format and the `LMT1:` taste-code prefix. Never rename those.
- User-visible text says "Nobody Listens". User-Agents use `NobodyListens/<version>` (no space). Files go under `Music/Nobody Listens/…`, `Nobody Listens Exports` and a `Nobody Listens` Drive folder.
- Logo: the traced worker from `../sub-brands/nobody-listens/` (rebuild the kit with `python -P build.py` there). `shared/src/main/res/drawable/nl_mark.xml` / `nl_mark_mono.xml` are generated by `tools/svg2vd.py`. It writes integer, relative path data because aapt2 corrupts any string over 32,767 characters, and the launcher then silently shows the default Android icon. App and Wear launchers are adaptive icons: a Paper background, with `nl_icon_foreground` / `nl_icon_monochrome` insets of 26 % so the art stays inside the round mask. The notification small icon is `nl_mark_mono`. Code references these as `com.nobodybuilds.listens.shared.R`.
- The party page (`assets/party/`) serves the kit's `favicon.svg`, which follows the guest's light/dark mode, plus `apple-touch-icon.png` from `PartyServerService`.
- CI (`build-release.yml`): every build makes arm64-v8a, armeabi-v7a and the watch APK. Releases pass `-Pnobodylistens.allApks=true`, which adds x86_64 and universal, and attach all of them.

## Design (Nobody Builds "Daylight" on Material 3)

The source is the sibling repo `NobodyBuilds-Design` (`tokens/tokens.json`, `docs/ui-brand-spec.md`). Always follow the Material 3 theme; never hand-roll colours, type or shapes.

- **Colours:** `ui/theme/Color.kt` `Daylight` holds the 53 light/dark tokens copied exactly from `tokens.json` (`DaylightSchemeTest` checks them and their contrast). `Theme.kt` maps them to M3 roles: primary = Blueprint, secondaryContainer = Sky, tertiary = accent ink (text-safe), **tertiaryFixed = Hard Hat**, surface = Paper / Night Shift, surfaceContainerLowest = white panel (light). In presentation code read `MaterialTheme.colorScheme` or the kit's `Nb.*` roles, never `Color(0x…)`. The exceptions are service-logo colours, artwork/illustration palettes (Garden, genre art, covers) and the OLED-black screensaver and sleep clock.
- **Hard Hat yellow** (`Nb.accent`, `NbButtonStyle.Accent`) is one bold moment per screen and only a **fill** with Night Shift on it. Never use it as text, thin graphics or progress on Paper: it is about 1.6:1 there. Use `Nb.ink` (Blueprint) for meters, rings, chart highlights and spinners.
- **Kit:** `presentation/nb/` (`NbButton`, `NbCard`, `NbChip`, `NbType`, `NbShapes`, `Nb`…) is the shared component layer. Restyle there, not per screen. Status = a word on a soft fill (`NbStatusChip`, `Nb.successSoft/successText`, `warningSoft/warningText`).
- **Shape and depth:** controls 10 dp, cards 16 dp, sheets 20 dp, buttons, chips and tags pill-shaped. **No shadows**: `surfaceTint` is transparent, and layers separate by surface steps plus `outlineVariant` hairlines. Only drag feedback, the brick-breaker game and the overlay over other apps keep elevation.
- **Type:** Gilroy open weights only (`gilroy_light.otf`, `gilroy_extrabold.otf`; free-font EULA in `licenses/`) for display and headings, Google Sans Flex (`gflex_variable.ttf`) for text, Unbounded (`NbType.accent`) for one accent phrase per layout. `GoogleSansRounded` is a legacy name: text weights map to Flex, Bold and up map to Gilroy ExtraBold.
- **Icons:** Material Rounded only: `Icons.Rounded.*` / `Icons.AutoMirrored.Rounded.*`, or Material Symbols Rounded vector drawables (`rounded_*_24.xml`, from `google/material-design-icons` `symbols/android/<name>/materialsymbolsrounded/`). Service logos (Telegram, Jellyfin, Navidrome, Subsonic, NetEase, QQ, Gemini, YouTube) and genre artwork keep their own drawings.
- **Settings › Appearance › App colours:** Daylight (stored value `"yuyu"`, kept from the old design so no migration is needed) or Material You. Album-art schemes stay on the player and detail screens (`nbPlayerScheme`, default accent Blueprint).
- **Pitch black (OLED):** an opt-in switch under App theme (hidden when the theme is Light), stored as `app_pitch_black_v1` in `ThemePreferencesRepository`. It is the one deliberate exception to the brand spec's "no black" dark mode. `DaylightPitchBlackColorScheme` makes the canvas `#000000` and steps cards up through Night Shift, keeping the dark scheme's accents and text (`DaylightSchemeTest` checks contrast). With Material You, `withPitchBlackCanvas()` blacks out only the canvas layers. Album-art player schemes and widgets are unchanged.
- **Widgets:** `ui/glancewidget/NbWidgetTheme.kt` plus `res/values(-night)/colors_nb_widget.xml`. The play button is Hard Hat with a Night Shift icon.

## YouTube Music (`data/ytmusic`, `presentation/ytmusic`)

Streams, downloads and video use the **VISIONOS** innertube client (`YouTubeMusicClients.STREAM`). As of 2026-10 it is the only client that returns direct googlevideo URLs which play to the end without a PO token or signature deciphering. ANDROID_VR, IOS_MUSIC and ANDROID_MUSIC hit bot checks. Plain IOS URLs are cut off after about 1 MB. WEB_REMIX is used only for browse and search.

Rules that each caused a real "won't play" bug:

- **Use `YouTubeMusicClients.http(okHttpClient)`, never the app-wide `OkHttpClient` directly.** The shared client rewrites `User-Agent` to `NobodyListens/1.0`, and googlevideo URLs are bound to the requesting client's User-Agent. In debug it also logs whole bodies, which buffers entire songs in memory.
- **Always send a `Range` header to googlevideo.** Requests without one stall forever. ExoPlayer sends none for position 0, so `YouTubeMusicStreamProxy` sets `alwaysRequestRange` and answers with a plain 200. The downloader fetches in 4 MB ranges.
- **Saved queues hold proxy URLs (`http://127.0.0.1:<port>/ytmusic/<id>`), and the port changes every launch.** `DualPlayerEngine`'s resolver calls `rebindStaleProxyUri` to point them at the running proxy.
- `resolveStream` shares one lookup per song and caches it until 30 minutes before the URL expires. The player, the proxy and the next-song pre-loader all ask for the same song at the same time.
- Only clients with `probeBeforeUse` (the IOS fallback) get their URL probed past 1.5 MB. VISIONOS URLs don't get cut off, so probing them only adds a round trip. A client that fails gets a 10-minute backoff.

Other behaviour:

- Tracks that actually play are saved to the `songs` table (`YouTubeMusicLibrary`, ids from `YouTubeMusicUris.songId`, source type `YTMUSIC`), so likes, playlists and stats work. The queue is only remembered; a track is saved when its stream is first prepared (`saveIfQueued`), so browsing a shelf doesn't flood the library. Existing rows get only a metadata update (`updateStreamedSongMetadata`), because `songs.is_favorite` is kept in sync from the favorites table by database triggers.
- Downloads take the highest-bitrate audio (Opus itag 251 on free accounts). `YouTubeMusicOpusRemuxer` copies it into a tagged `.opus` file without re-encoding, saved under `Music/Nobody Listens/YouTube Music`.
- Video plays the HLS manifest from the same VISIONOS response in `YouTubeMusicVideoActivity` (needs `media3-exoplayer-hls`). It opens in landscape with the system bars hidden, and a gear menu picks the quality (Auto or a fixed height). As of 2026-10, VISIONOS responses carry no ad placements and the HLS has no ad segments.
- The video activity is `singleTask` in its own task (`taskAffinity` `${applicationId}.video`) with `supportsPictureInPicture`. Back or Home while playing enters PiP, which has a play/pause `RemoteAction`; closing PiP finishes the activity. It connects a `MediaController` to `MusicService`: if that song (`YouTubeMusicUris.songId`) is current, the video starts at its position and pauses it, and on close the song is seeked to the video's position.
- YouTube WebM streams report no bitrate to ExoPlayer. `PlayerViewModel` takes it from `DualPlayerEngine.knownStreamBitrate`, so the label shows kbps and the player doesn't re-read the stream with `MediaMetadataRetriever`. 48 kHz is YouTube's maximum sample rate (Opus is always 48 kHz).
- Start time on the x86_64 emulator is mostly the emulator itself: about 1 s of DNS per new googlevideo host, and slow software Opus decoder setup. Measure on a real phone before optimising further.
- Settings › Playback › YouTube Music has a streaming quality and a download quality setting (`YouTubeMusicAudioQuality`: High, Normal, Data saver), stored in the plain `ytmusic_settings` prefs. Each one caps the bitrate in `YouTubeMusicFormats.ranked`. Downloads pass `opusOnly`, so every download can be remuxed to a tagged `.opus` file. The stream cache key includes the quality.
- Search suggestions from YouTube are **off by default** (Settings › Playback › YouTube Music › Search suggestions, `search_suggestions` in `ytmusic_settings`). `YouTubeMusicRepository.searchSuggestions` returns nothing while it is off, so neither search box sends keystrokes to YouTube.
- Search runs the YouTube Music search and a plain youtube.com video search (`WEB` client, videos-only params) at the same time. Videos not already in the music results are added as a "YouTube videos" shelf.
- **Offline first:** YouTube features only touch YouTube songs (`ytmusic://`) or YouTube places (the YouTube Music screen, Search with the YouTube chip on). Phone songs never go online for them.
- **Radio:** `next` with `RDAMVM<id>` gives about 50 songs and a continuation. `YouTubeMusicRadio` remembers the radio's song ids, and `PlayerViewModel.onMediaItemTransition` appends the next batch when three or fewer songs are left. It starts from "Start radio" in the song sheet.
- **Pages:** `YouTubeMusicPlaylist.kind` is PLAYLIST, ALBUM (`MPREb_`) or ARTIST (`UC`, only when `pageType` is `MUSIC_PAGE_TYPE_ARTIST`). The dashboard VM keeps a page stack so back goes artist → album → back.
- **Lyrics:** for YouTube songs, `LyricsRepositoryImpl` tries the lyrics API (synced) and then YouTube's plain lyrics (the `MPLY…` browse page from `next`). Embedded and local lyrics are skipped because there's no file.
- **Account sync:** `MusicRepositoryImpl.setFavoriteStatus` calls `YouTubeMusicAccountSync`, which sends `like/like` or `like/removelike` only for YouTube songs and only when signed in.
- **Thumbnails:** `YouTubeMusicThumbnails`. Album art is requested at 800px, or 1200px for download covers. For video thumbnails it tries maxresdefault → hq720 → sddefault → hqdefault and crops the download cover square. When the HD cover is found after playback starts, `YouTubeMusicLibrary.artworkUpdates` swaps it into the player.
- **Cache:** `YouTubeMusicCache` is a 1 GB LRU `SimpleCache` used only for YouTube streams, routed in `DualPlayerEngine`. Songs not played for 7 days are removed at startup.
- **Library:** the source filter cycles All → Cloud → Phone → Downloaded. `StorageFilter.DOWNLOADED` is SQL `filterMode = 3`: phone files under `…/Nobody Listens/YouTube Music` (the path is hard-coded in `MusicDao`'s queries and `LibrarySourceFilter.DOWNLOADS_FOLDER_SUFFIX`; change both together).
- Search, feed, play, download and video work signed out. Only the Library tab needs the account cookie.
